# رشد — SEO Agent

فضای کار محلی و فارسی برای شناخت سایت، پیشنهاد موضوع، تولید مقاله با منابع، بازبینی و انتقال به WordPress.

## اجرا در ویندوز

Python 3.10 یا جدیدتر لازم است. در پوشه پروژه اجرا کنید:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe main.py
```

برنامه در http://127.0.0.1:8000 در دسترس است. اگر venv از قبل وجود دارد، مرحله اول را تکرار نکنید. در صفحه شروع، «دیدن پروژه نمونه» تمام مسیر رابط را بدون کلید API و تماس با سرویس خارجی نشان می‌دهد.

## استفاده واقعی

1. در تنظیمات، کلید OpenAI و نام مدل پشتیبان Responses API و Structured Outputs را وارد کنید. مدل پیش‌فرض `gpt-4.1-mini` است؛ دسترسی به آن به حساب شما بستگی دارد. متغیرهای `OPENAI_API_KEY` و `OPENAI_MODEL` در `.env` نیز پشتیبانی می‌شوند. فایل `.env` موجود دست‌نخورده باقی می‌ماند.
2. سایت عمومی HTTPS را با آدرس نهایی و بدون redirect به دامنه دیگر ثبت کنید. نصب وردپرس در زیرپوشه نیز پشتیبانی می‌شود؛ آدرس همان زیرپوشه را بدهید. درباره کسب‌وکار، مخاطب، لحن و موضوع‌های ممنوع بنویسید.
3. «تحلیل و پیشنهاد» حداکثر ۱۲ صفحه را با رعایت robots.txt می‌خواند. داده‌های جمع‌آوری‌شده و اطلاعات برند برای پیشنهاد موضوع به مدل فرستاده می‌شوند.
4. موضوع پیشنهادی یا موضوع دلخواه انتخاب کنید. تا چهار URL منبع تکمیلی می‌توانید وارد کنید. متن این منابع خوانده می‌شود و مدل فقط اجازه استناد به URLهای خوانده‌شده را دارد. این برنامه موتور جست‌وجوی وب یا سرویس حجم جست‌وجوی کلمات کلیدی ندارد.
5. مقاله را در ویرایشگر باز کنید. HTML، عنوان، خلاصه، نامک خروجی و توضیحات متا قابل ویرایش‌اند. پیش‌نمایش در iframe بدون اجرای اسکریپت نشان داده می‌شود. امتیاز مقاله فقط بررسی ساختار است؛ صحت ادعاها یا رتبه را تأیید نمی‌کند.
6. در وردپرس یک کاربر نویسنده با دسترسی به نوشته‌های خودش بسازید. از «کاربران ← شناسنامه ← رمزهای برنامه» یک Application Password اختصاصی بسازید. نام کاربری و این رمز را در صفحه اتصال وارد کنید. نیاز به رمز اصلی مدیر نیست.
7. مقاله را به صورت draft ارسال کنید. برای انتشار یا زمان‌بندی، نسخه ذخیره‌شده را از نظر ادعاها و منابع تأیید و بعد روش انتشار را انتخاب کنید. هر ویرایش، تأیید قبلی را باطل می‌کند. زمان ورودی رابط، ساعت محلی دستگاه است و به UTC برای WordPress تبدیل می‌شود. زمان‌بندی نهایی را WP-Cron سایت اجرا می‌کند.

«شروع جریان تولید» مراحل تحلیل، پیشنهاد و نگارش حداکثر ۵ مقاله را به ترتیب انجام می‌دهد؛ ارسال خودکار **پیش‌نویس** به وردپرس اختیاری است. انتشار عمومی همواره نیازمند تأیید صریح همان نسخه است. هر سایت سقف ۱۰ مقاله در روز UTC دارد. هزینه استفاده از مدل به حساب API شما تعلق دارد؛ محدودیت مالی دلاری در برنامه اعمال نمی‌شود.

## طراحی

```text
رابط فارسی HTML / CSS / JavaScript
          │ API همان مبدأ + CSRF
          ▼
FastAPI → SQLite: سایت‌ها، موضوع‌ها، نسخه مقاله، عملیات و گزارش
          │
          ├─ Worker تک‌پردازشی: صف ماندگار و لغو بین مراحل
          ├─ Crawler: robots.txt، sitemap، حداکثر ۱۲ صفحه
          ├─ Writer: Responses API + خروجی ساختاریافته Pydantic
          ├─ Quality: پاک‌سازی HTML، بررسی ساختار و عنوان تکراری
          └─ WordPress Connector: draft / publish / future
```

- `main.py`: ورودی اجرا
- `seo_agent/api.py`: API، اعتبارسنجی، کنترل نسخه، تأیید و رابط
- `seo_agent/worker.py`: گردش‌کار و صف پایدار
- `seo_agent/crawler.py`: خواندن محتوا و sitemap
- `seo_agent/ai.py`: پرامپت‌ها، schema و مدیریت خطاهای مدل
- `seo_agent/wordpress.py`: اتصال REST API وردپرس
- `seo_agent/network.py`: HTTPS عمومی، کنترل DNS، اتصال به IP اعتبارسنجی‌شده با حفظ SNI، جلوگیری از انتقال credential در redirect و محدودیت حجم پاسخ
- `seo_agent/security.py`: رمزنگاری Fernet برای credentialهای سایت و کلید مدل
- `seo_agent/content.py`: پاک‌سازی HTML و کنترل‌های ساختاری
- `static/`: رابط فارسی راست‌به‌چپ بدون وابستگی frontend یا CDN
- `tests/`: آزمون‌های یکپارچه آفلاین و رفتار connectorها

## ذخیره‌سازی و امنیت

داده‌ها در `data/seo.sqlite3` و کلید رمزنگاری در `data/vault.key` ذخیره می‌شوند. دسترسی فایل‌های این پوشه باید محدود به حساب سیستم‌عامل شما باشد؛ کلید محلی جایگزین vault سازمانی نیست. برای بازیابی credentialها باید هم دیتابیس و هم کلید رمزنگاری را نگه دارید. در صورت استفاده از متغیر `SEO_ENCRYPTION_KEY` همان کلید را نیز حفظ کنید. از `data/` و `.env` در Git یا فضای عمومی نسخه تهیه نکنید. محتوای مقاله‌ها و اطلاعات برند در دیتابیس محلی متن ساده‌اند؛ فقط secretها رمزنگاری می‌شوند.

کلیدها هرگز وارد prompt مدل، پاسخ API یا گزارش فعالیت نمی‌شوند. اطلاعات ورودی صفحات untrusted در نظر گرفته می‌شود. مدل ابزار انتشار یا دسترسی به credentialها ندارد؛ تصمیم انتشار به backend و تأیید کاربر وابسته است. HTML با allowlist پاک‌سازی می‌شود. پیش‌نمایش sandbox دارد. درخواست‌های تغییردهنده نیازمند CSRF و مبدأ معتبرند. این محافظت‌ها مجوز انتشار اینترنتی بدون احراز هویت نیستند.

برنامه را **فقط روی loopback و با یک process** اجرا کنید. از `--host 0.0.0.0` یا چند worker استفاده نکنید. این نسخه سرویس تیمی، SaaS یا محصول آماده استقرار عمومی نیست. برای آن کاربرد به احراز هویت، جداسازی کاربران، مدیریت مستقل secretها، migration و صف توزیع‌شده نیاز دارید.

## رفتار در خطا

- صف روی دیسک ذخیره می‌شود. بعد از restart، عملیات در حال اجرا fail می‌شود و عملیات queued ادامه پیدا می‌کند. مقاله‌های تکمیل‌شده در جریان چندمقاله‌ای حفظ می‌شوند.
- لغو در مرز مراحل اجرا می‌شود؛ درخواست در حال انجام مدل/شبکه ابتدا پاسخ می‌گیرد. ارسال در حال اجرای وردپرس قطع نمی‌شود.
- اگر نتیجه نوشتن وردپرس نامشخص باشد، وضعیت مقاله `uncertain` می‌شود. «بررسی وضعیت وردپرس» به صورت read-only و با slug یکتا نوشته را پیدا می‌کند. عملیات نوشتن به طور خودکار تکرار نمی‌شود. اگر نوشته پیدا نشود، برای جلوگیری از ایجاد نسخه تکراری، بررسی دستی پنل لازم است.
- slug وردپرس به شکل ثابت `seoagent-<article-id>` است تا پس از timeout بتوان نوشته را پیدا کرد. نامک پیشنهادی مقاله در خروجی JSON نگهداری می‌شود؛ تغییر slug در پنل وردپرس بازیابی خودکار را مختل می‌کند.
- تأیید مقاله معادل تأیید revision مشخص است؛ تغییر متن، عنوان یا متادیتا نیازمند بازبینی تازه است.

## دامنه نسخه اول

پشتیبانی از WordPress خودمیزبان با REST API استاندارد؛ اتصال WordPress.com، CMSهای دیگر و SEO pluginها پیاده نشده‌اند. متن، عنوان و excerpt به وردپرس منتقل می‌شوند. meta description و نامک پیشنهادی در خروجی JSON موجودند؛ ثبت meta در Yoast/Rank Math به connector اختصاصی نیاز دارد. تولید/آپلود تصویر شاخص، بررسی رندر JavaScript سایت، تحقیق رقبا و SERP، Search Console، Analytics، تشخیص معنایی کامل cannibalization، شمارش توکن/صورتحساب و راستی‌آزمایی مستقل ادعاها در این نسخه وجود ندارند. عنوان تکراری و منابع ناشناخته کنترل می‌شوند، اما این‌ها جای بررسی متخصص را نمی‌گیرند.

## آزمون

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
node --check static/app.js
```

آزمون‌ها در پوشه موقت اجرا می‌شوند و از کلید واقعی، اعتبار مدل یا وردپرس واقعی استفاده نمی‌کنند. مسیر تحلیل ← پیشنهاد ← تولید، کنترل نسخه و تأیید، رمزنگاری، جلوگیری از SSRF، پاک‌سازی HTML، بازیابی ارسال نامشخص و کنترل زمان انتشار پوشش داده شده‌اند.
